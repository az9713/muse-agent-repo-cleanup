The Case of the Missing Traffic Numbers

A GitHub dashboard said “n/a.” What followed was a compact lesson in credentials, API clients, stubborn editors, careful verification—and an honest recovery from one self-inflicted bug.

01The setup

A dashboard with two blank clues

Inside ECC-tutorial, the workflow at .github/workflows/monthly-metrics.yml maintains issue #24 as a month-by-month project dashboard. Most of the table was healthy. Package downloads, stars, forks, contributors, and releases all had values. Two columns did not: Views (14d) and Clones (14d) kept falling back to “n/a.”

Those two values come from GitHub’s traffic API. The ordinary GITHUB_TOKEN that Actions provides cannot read that private repository traffic data; GitHub answers it with a 403, “Resource not accessible by integration.” The workflow already anticipated that limitation. If a repository secret named TRAFFIC_STATS_TOKEN contained a personal access token from an account with push access, it would use the stronger credential. Without one, it would degrade gracefully to “n/a.”

The mission was narrow: create the token, store it safely as the repository secret, and prove that real traffic numbers reached the dashboard.
02The credential

A key made for the job

A classic personal access token was created with only the repo scope. The classic form was deliberate: it could be configured without an expiration date, avoiding a periodic reset for a long-running monthly report. GitHub sign-in still required two-factor authentication. The first mobile approval was missed; a second succeeded. The safeguard was respected throughout—never bypassed.

The credential was then stored as the Actions secret TRAFFIC_STATS_TOKEN. GitHub confirmed that the secret had been updated. At that point, the obvious expectation was that the next run would fill the two empty columns.

03The mystery

Three green runs, zero traffic

Three workflow runs completed successfully. Yet issue #24 still said “n/a.” A green run only proved the workflow had survived; it did not prove the right credential had reached the right endpoint. The decisive clue came from the token’s own settings page: Last used: Never used.

That clue shifted the investigation away from permissions and toward the code path. The workflow’s getTraffic() function used the pre-authenticated client supplied by actions/github-script. It tried to pass the personal token in a custom Authorization header. But the client’s authentication hook silently replaced that header with its own default GITHUB_TOKEN. Every request looked correct in source, left with the wrong identity, and died at the traffic endpoint.

$ inspect token usage
Last used: Never used

$ inspect traffic request
client auth: GITHUB_TOKEN → 403
intended auth: TRAFFIC_STATS_TOKEN

The repair was conceptually small: stop routing this call through github.request(). Send the personal token directly with plain fetch(), outside the client that was rewriting the header.

04The repair

When the editors fought back

The diagnosis was clean; entering the fix was not. GitHub’s CodeMirror editor and the Monaco editor in github.dev both rejected or mangled automated typing. The human pasted the replacement function from a local laptop, but the transfer stripped the twelve-space indentation required by the YAML-embedded JavaScript.

So the work split at the interface boundary. The human supplied the text; the agent repaired its shape. Using only keyboard Space presses, twelve spaces were prepended to each of twenty-one lines. The result was checked through GitHub’s API rather than trusted by appearance. When the source-control message field also resisted automated text, the human typed the short commit message and pressed Commit and Push.

The corrected edit landed on az9713-patch-2 as commit 2589c4fa, then merged through PR #28. Merge commit: 38af54b. Temporary patch branches were removed after the merge.

Autonomy did not mean pretending the interface worked. It meant changing tactics, minimizing the human’s role to the one action the interface required, and verifying the resulting artifact independently.
05The twist

The detective left the comma

The merged workflow ran—and failed immediately with SyntaxError: Unexpected token ','. The replacement block supplied by the agent ended with }, where the function required only }. This was not a GitHub quirk or a paste problem. It was the agent’s mistake.

Owning that error made the next step simple. A fully corrected file was prepared locally, then uploaded over the broken version through GitHub’s web upload path, avoiding the editors that had caused trouble earlier. Commit fd77062, “Fix syntax error: remove stray comma after getTraffic,” put the corrected workflow on main.

The proof was in the dashboard

Workflow run #13 completed successfully. More importantly, issue #24’s September 2026 row no longer showed a fallback. The traffic API returned real values—a result the default Actions token cannot produce.

THE SHORT VERSION

A session in seven turns

The work moved from access, to observation, to diagnosis, to recovery. Human involvement appeared only where a protected approval or a stubborn interface required it.

  1. TURN 01

    Create the credential

    A classic, repo-scoped personal access token was created; the human approved GitHub’s second-factor prompt.

  2. TURN 02

    Store the secret

    The token was saved as TRAFFIC_STATS_TOKEN in ECC-tutorial’s Actions secrets.

  3. TURN 03

    Challenge the green result

    Three successful runs still produced “n/a,” so the visible outcome—not the green check—became the test.

  4. TURN 04

    Follow the unused token

    “Never used” revealed that the credential was not reaching the traffic endpoint.

  5. TURN 05

    Work around the editors

    The human pasted once; the agent restored indentation line by line and verified the branch through the API.

  6. TURN 06

    Own and repair the regression

    A stray comma caused a syntax failure. The agent acknowledged it, replaced the file, and ran again.

  7. TURN 07

    Verify the real outcome

    Run #13 passed, and issue #24 displayed 232 views and 460 clones.

FIELD NOTES

What this session taught

  1. Usage metadata is evidence. “Never used” turned a vague permissions problem into a precise routing problem.
  2. Pre-authenticated clients have opinions. A credential in source code is not proof that the credential survived the client’s auth middleware.
  3. Interface failure is not task failure. When typing broke, the method changed: human paste, keyboard-only indentation, API verification, then file upload.
  4. Verify the artifact, not the ceremony. A green Actions run was insufficient. The dashboard values—and the traffic API’s protected response—were the proof.
  5. Autonomy includes candor. The stray comma belonged to the agent. Naming that plainly made recovery faster and kept the collaboration trustworthy.
